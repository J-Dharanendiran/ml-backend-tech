## 🗺️ The big picture

Your FastAPI application is essentially a **server**. When a client sends:

```http
GET /view
```

your application receives it, looks for a matching route:

```python
@app.get('/view')
```

and runs:

```python
def view():
```

That function loads the patient data and returns it. FastAPI turns the returned Python object into an HTTP response:

```text
Client
   │
   │  GET /view
   ↓
FastAPI
   │
   │ finds @app.get('/view')
   ↓
view()
   │
   ↓
load_data()
   │
   ↓
patients.json
   │
   ↓
Python dictionary
   │
   ↓
FastAPI converts it to JSON
   │
   ↓
HTTP Response
   │
   ↓
Client
```

That's the whole game. Humans invented HTTP, then spent decades adding frameworks to avoid writing HTTP by hand. 😌

## 🧰 The helper: `load_data()`

```python
def load_data():
    with open('patients.json','r') as f:
        data = json.load(f)

        return data
```

This is **ordinary Python**, not specifically FastAPI. Its job:

> Open `patients.json` → read it → convert it into Python data → return it.

### 📖 `open('patients.json','r')`

You open the file `patients.json`, and `'r'` means **read mode**. You are not modifying the file, only reading it.

### 🤔 "Why `with`?"

The `with` statement manages the file for you. When the block ends, Python **automatically closes** the file.

Without `with`, you would close it by hand:

```python
f = open('patients.json', 'r')

data = json.load(f)

f.close()
```

With `with`:

```python
with open('patients.json','r') as f:
    data = json.load(f)
```

Less opportunity for humans to forget things. A rare victory.

### 🔄 `json.load(f)`

This reads the JSON file and converts it into Python objects. Now `data` holds your patient information as a Python dictionary.

### ↩️ `return data` inside the `with` block

In your fixed code the `return data` sits **inside** the `with` block:

```python
    with open('patients.json','r') as f:
        data = json.load(f)

        return data
```

That works: the data is already loaded before the function returns, and the file still closes on the way out. Placing `return` after the block also works and is a common style. Both give the same result here.

```text
load_data()
     │
     ↓
patients.json
     │
     ↓
JSON data
     │
     ↓
return data
     │
     ↓
data variable
```

## 🌐 Now we reach HTTP GET

This is the important part. You wrote:

```python
@app.get("/dharan")
```

The `.get()` tells FastAPI:

> *"Create a route that responds to HTTP GET requests."*

### 📥 "What is an HTTP GET request again?"

Remember the CRUD mapping:

```text
CREATE    → POST
RETRIEVE  → GET
UPDATE    → PUT
DELETE    → DELETE
```

**GET = retrieve / read information.** When a client wants information from your API, it sends:

```http
GET /view
```

> *"Server, give me the information available at `/view`."*

### 🧩 "What does `/view` mean?"

```python
@app.get('/view')
```

has two pieces:

```text
@app.get
     │
     └── HTTP method

'/view'
   │
   └── path
```

```text
HTTP Method     Path
    ↓             ↓
   GET          /view
    │             │
    └─────┬───────┘
          ↓
       Endpoint
```

An **endpoint** is a particular URL / path in your API associated with an operation.

### 🎀 "What is that `@` symbol?"

It is a Python **decorator**. It attaches the function underneath it to that FastAPI route:

```python
@app.get('/view')
def view():
```

> When a GET request arrives at `/view`, execute `view()`.

```text
GET /view
    │
    ↓
@app.get('/view')
    │
    ↓
view()
```

## 🚪 Door 3: `/patient/{patient_id}`, the one that finds a person

```python
@app.get('/patient/{patient_id}')
def view_patient(patient_id: str = Path(..., description= 'ID of the patient', example='P001')):
    # load all the patients
    data = load_data()

    if patient_id in data:
        return data[patient_id]
    return {'error': 'patient not found'}
```

This is the most interesting door. It has **three ideas** stacked together. Take them one at a time.

### 🧩 Idea 1: the path parameter `{patient_id}`

```python
@app.get('/patient/{patient_id}')
```

The curly braces mark a **dynamic part of the URL**:

```text
/patient/{patient_id}
          │
          ↓
      patient_id
          │
          ↓
function parameter
```

```text
GET /patient/P001  →  patient_id = "P001"
GET /patient/P002  →  patient_id = "P002"
```

FastAPI extracts the value from the URL and hands it to your function's parameter of the **same name**.

### 🏷️ "What does `: str` mean?"

`patient_id: str` is a Python **type annotation**. You are saying:

> `patient_id` should be treated as a string.

This fits your data, because IDs like `P001` are text. (If your IDs were plain numbers you might use `int` instead.)

### 🛤️ Idea 2: `Path(...)`, describing the parameter

```python
patient_id: str = Path(..., description= 'ID of the patient', example='P001')
```

`Path()` gives FastAPI **extra information about the path parameter**:

| Piece | What it does |
|---|---|
| `...` | Means **required**. The value has no default. |
| `description='ID of the patient'` | Human-readable text shown in the API documentation |
| `example='P001'` | An example value shown in the documentation |

> This is where the automatic documentation from the *"fast to code"* chapter shows up in your own code. `description` and `example` feed the interactive docs page.

A path parameter is always required (the URL itself contains it), which is why the default is `...`.

### 🔎 Idea 3: the lookup and the "not found" branch

```python
data = load_data()

if patient_id in data:
    return data[patient_id]
return {'error': 'patient not found'}
```

Read it slowly:

1. `load_data()` reads the whole file into a dictionary.
2. `patient_id in data` asks: **is this ID one of the dictionary's keys?**
3. If yes, `data[patient_id]` returns **just that patient's record**.
4. If no, the function returns an error message instead.

```text
GET /patient/P001
        │
        ↓
patient_id = "P001"
        │
        ↓
load_data()
        │
        ↓
"P001" in data ?
     ┌──┴──┐
    Yes    No
     │      │
     ↓      ↓
data["P001"]   {'error': 'patient not found'}
     │      │
     └──┬───┘
        ↓
   HTTP Response
```

With the illustrative file above:

```http
GET /patient/P001
```

```json
{
    "name": "Dharan",
    "age": 21,
    "city": "Salem"
}
```

```http
GET /patient/P999
```

```json
{
    "error": "patient not found"
}
```

### 🎯 Why the earlier trap is gone

Before, the function *received* `patient_id` but returned **all** patients. Now the two concepts are both there:

```text
1. Receive patient_id           ✅  (path parameter + Path)
2. Use it to find the patient   ✅  (if patient_id in data → data[patient_id])
```

Because your keys are strings like `"P001"` and your parameter is `str`, the types line up, so the lookup can match.

## 📖 Vocabulary sheet

| Term | Meaning |
|---|---|
| **`FastAPI`** | The class you use to create your application |
| **`app`** | Your application object; routes attach to it |
| **Route / endpoint** | A method + path pair tied to a function, such as `GET /view` |
| **Decorator (`@`)** | Attaches the function below it to a route |
| **`@app.get(...)`** | Declares a route that answers HTTP GET requests |
| **Path** | The URL portion after the domain, like `/view` |
| **Path parameter** | A dynamic part of the path, written `{patient_id}` |
| **Type annotation** | `patient_id: str` declares the expected type |
| **`Path()`** | FastAPI helper that describes / validates a path parameter |
| **`...` (Ellipsis)** | Used in `Path(...)` to mean "required" |
| **`in` on a dict** | Checks whether a key exists |
| **`open(..., 'r')`** | Open a file in read mode |
| **`with`** | Manages a resource and closes it automatically |
| **`json.load()`** | Reads JSON from a file into Python objects |

## 🌀 Deepest Realization

Every GET endpoint is one sentence:

> **"When someone asks for *this path*, run *this function*, and send back whatever it returns."**

Your third door adds only one more idea: **the path can carry a value**, and the function can use that value to decide *which* thing to return. FastAPI does not hide HTTP. It gives you a **doorbell wired to a Python function**.
