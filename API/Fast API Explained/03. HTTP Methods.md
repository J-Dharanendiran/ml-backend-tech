# 🗣️ The Four Verbs of the Internet: CRUD and HTTP Methods

> *"You know what an API is. You know why FastAPI is fast. But when a request arrives at your server, how does the server know whether you want to read something, add something, change something, or destroy something?"*

Before the FastAPI project begins, the instructor wants HTTP methods to feel **intuitive**, not memorized. His chain of thought:

> **Software interaction → CRUD → websites → HTTP requests → HTTP methods → FastAPI endpoints.**

## 🤔 "Why do HTTP methods matter at all?"

Before any HTTP, he asks a simpler question: **what kind of interaction do users have with software?** He splits software into two broad categories:

```text
Software (by user interaction)
│
├── Static software
└── Dynamic software
```

That split is the doorway to understanding why different HTTP methods exist.

---

## 🕰️ Static software: look, don't touch

Static software is software the user does not interact with much. The instructor's example is a **calendar**. You open it and:

- see today's date
- see what day it is
- look at future dates

Not much two-way interaction. The software mainly **gives you information**:

```text
Software
   ↓
Information
   ↓
User
```

Another example: a **clock**. You look at it, you get the time, that's it. Humanity has somehow turned "look at the clock" into a software category. 😄

---

## 🎛️ Dynamic software: talk back

Dynamic software is different: the user can do many things. His example is **Microsoft Excel**. You can:

- create worksheets
- enter data
- view existing data
- modify existing data
- analyze data
- delete data

```text
User → Software → User → Software → ...
```

Two-way interaction.

---

## 🔑 The key idea: CRUD

> **No matter how complicated a dynamic application looks, user interactions fundamentally fall into four categories.**

| Letter | Meaning | What it means |
|---|---|---|
| **C** | Create | Create something new |
| **R** | Retrieve | Get / view existing information |
| **U** | Update | Modify existing information |
| **D** | Delete | Remove existing information |

### 📊 Excel through CRUD

```text
Create    → Create a new cell / data entry
Retrieve  → View existing data
Update    → Change existing data
Delete    → Remove existing data
```

```text
                 CRUD
                  │
     ┌─────────┬──┴───────┬─────────┐
     ↓         ↓          ↓         ↓
  Create   Retrieve    Update    Delete
```

He applies the same idea to Microsoft Word: create a document, read an existing one, modify it, or delete it.

---

## 🌐 "But websites are software too?"

Yes, and this is the important pivot. **A website is also software.** The difference is **where it runs**.

**Excel:** installed on your machine, used on that same machine.

```text
Your computer
     │
     └── Excel
```

**A website:** running on a *different* machine.

```text
                Internet
                   │
        ┌──────────┴──────────┐
        ↓                     ↓
     Client                 Server
   Your machine          Website/API
```

- Your machine is the **client**.
- The machine running the website is the **server**.
- They communicate through **HTTP**.

---

## 📰 Static websites vs. 📸 dynamic websites

He applies the same split to websites.

**Static website:** little user interaction. Examples: blogs, some government websites. The user mostly *consumes* information.

**Dynamic website:** lots of interaction. His example is **Instagram**. You can:

- log in
- create posts
- comment
- like posts
- reply to comments
- edit your profile
- delete posts
- delete comments

Every one of those can be categorized using CRUD.

### 📸 Instagram → CRUD

```text
Create    → Create a post, upload a photo, write a comment
Retrieve  → Scroll your feed, view someone's profile, view posts
Update    → Edit your profile, edit your comment
Delete    → Delete a post, delete a comment
```

### 🍔 Zomato → CRUD

His second example is a food-ordering website:

```text
Create    → Place a new order
Retrieve  → Look at your previous orders
Update    → Modify your address
Delete    → Delete an address
```

Same four verbs, different app.

---

## ✉️ Now the real problem: HTTP

A dynamic website operates over the internet, so every interaction is a conversation:

```text
Client                         Server
  │                              │
  │──── HTTP Request ──────────→│
  │                              │
  │←──── HTTP Response ─────────│
```

The client sends an **HTTP request**. The server receives it, figures out what the client wants, performs the operation, and sends back an **HTTP response**.

### 🧩 "But how does the server know what I want?"

This is the central reason HTTP methods exist. A bare request is not enough. The server needs a signal about **which kind of operation** you want:

```text
"I want to retrieve a patient's profile."
"I want to create a new patient."
"I want to update this patient."
"I want to delete this patient."
```

These are four different operations. So HTTP gives us **methods** that communicate the intended type of operation. The instructor describes them as *verbs* added to the HTTP request.

---

## 📥 GET → Retrieve

You want to read something: *"Give me this patient's profile."* That is a **Retrieve**, and the method is:

```http
GET
```

```http
GET /patients/5
```

> "I want to retrieve patient 5."

The instructor explains GET as the client saying it wants to retrieve something from the website.

---

## 📤 POST → Create

You fill out a form with a new patient's information and want the server to create a record. That is a **Create**, and the method is:

```http
POST
```

```http
POST /patients
```

with the patient information in the request. The instructor's examples include:

- a login form
- a registration form
- sending information to a website

### ⚠️ Nuance the instructor simplified

The lesson treats POST as **Create**, which is a good way to learn CRUD. In real HTTP / API design, POST is more generally used to submit data for processing or to request creation of a subordinate resource. So do not hard-code in your head:

> ~~POST always means Create.~~

The lesson itself presents the simplified CRUD mapping.

---

## ✏️ PUT → Update

Patient #5 already exists and currently has:

```text
Weight = 70 kg
```

The doctor wants to modify the information. That is an **Update**, which the instructor maps to:

```http
PUT
```

```http
PUT /patients/5
```

The server reads this as an update operation for that resource.

---

## 🗑️ DELETE → Delete

The doctor wants to remove a patient's record. That is a **Delete**:

```http
DELETE
```

```http
DELETE /patients/5
```

> "Delete patient 5."

The instructor explains that DELETE tells the server the client wants a deletion.

---

## 🧠 The mapping worth memorizing

| CRUD operation | HTTP method | Meaning |
|---|---|---|
| **Create** | `POST` | Create / send a new resource |
| **Retrieve** | `GET` | Retrieve / read data |
| **Update** | `PUT` | Update an existing resource |
| **Delete** | `DELETE` | Delete a resource |

```text
                 CRUD
                  │
   ┌───────────┬──┴────────┬───────────┐
   ↓           ↓           ↓           ↓
 CREATE     RETRIEVE     UPDATE      DELETE
   │           │           │           │
   ↓           ↓           ↓           ↓
 POST         GET         PUT       DELETE
```

The instructor calls these the four most commonly used HTTP methods in this discussion, with **GET and POST used more often than PUT and DELETE**.

Now everything connects. The project is a **patient management API**. It will let a doctor:

1. create patients
2. view patients
3. view a particular patient
4. update patients
5. delete patients

The instructor says the backend will initially store the records in a **JSON file instead of a database**, keeping the basic approach similar.

```text

        ┌──────────────┼──────────────┐
        │              │              │
       POST           GET            PUT           DELETE
        │              │              │              │
     Create         Retrieve        Update         Delete
     patient        patients        patient        patient
```

The endpoints: create a patient, view all patients, view a specific patient, update a patient, delete a patient.

Suppose your JSON "database" contains:

(These values are illustrative sample data, not real records.)

**Create a patient**


> Give me all patients.

**Get one patient**

## 🧭 Three things people confuse

| Thing | What it describes |
|---|---|
| **CRUD** | *What operation* you want: Create, Retrieve, Update, Delete |
| **HTTP methods** | *How the request signals that operation*: POST, GET, PUT, DELETE |
| **FastAPI** | The framework you use to *build the API that receives and handles* those requests |

```text
User / Frontend
       │
       │ HTTP Request
       ↓
   FastAPI API
       │
       ├── GET     → retrieve
       ├── POST    → create
       ├── PUT     → update
       └── DELETE  → delete
       │
       ↓
    Data / DB
       │
       ↓
 HTTP Response
       │
       ↓
     Client
```

## ⏱️ The one-minute version

> **Dynamic applications let users manipulate data. Those interactions can be understood as CRUD. When the interaction happens over HTTP, HTTP methods tell the server the intended operation.**

```text
CRUD                 HTTP

Create      ───────→ POST
Retrieve    ───────→ GET
Update      ───────→ PUT
Delete      ───────→ DELETE
```

```text
Frontend
   │
   │ HTTP Request  (GET / POST / PUT / DELETE)
   ↓
FastAPI
   │
   │ performs operation
   ↓
Database / JSON
   │
   ↓
HTTP Response
   │
   ↓
Frontend
```

The instructor ends the section by stressing that these methods will be used when designing the project's endpoints.

## 📖 Vocabulary sheet

| Term | Meaning |
|---|---|
| **Static software** | Little user interaction; mainly provides information (calendar, clock) |
| **Dynamic software** | Rich two-way user interaction (Excel, Word) |
| **CRUD** | Create, Retrieve, Update, Delete: the four basic data operations |
| **Client** | The machine / software making a request |
| **Server** | The machine running the website / API |
| **HTTP request** | Message from client to server |
| **HTTP response** | Message from server back to client |
| **HTTP method** | The signal in a request that says which operation is intended |
| **GET** | Retrieve data |
| **POST** | Create / submit data (simplified as Create in the lesson) |
| **PUT** | Update an existing resource |
| **DELETE** | Delete a resource |
| **Endpoint** | A specific URL path an API exposes, such as `/patients/1` |

## ✅ Sanity Check

- **POST ≠ always Create.** In real API design, POST is more general (submit data for processing, or create a subordinate resource). The lesson uses the CRUD simplification.
- **The method is not a "verb inside the body."** The instructor's wording ("verbs added to the HTTP request") is simplified. The method lives in the **request line / request metadata**, and the body is a separate part of the request. This matters once you inspect real requests in FastAPI.
- Both points come from the notes you provided. I did not verify them against external documentation for this chapter.

## 🌀 Deepest Realization

Every app you have ever used, from Excel to Instagram to Zomato, is the same four verbs wearing different costumes:

> **Make something. Look at something. Change something. Remove something.**

HTTP methods are just the internet's way of *saying which verb you mean*. FastAPI is where you decide what happens when each one arrives.
